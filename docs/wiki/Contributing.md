# Contributing Guidelines

## Core Quality Standards

### 1. Title Case All User-Facing Strings
Every string displayed to the user &mdash; button labels, modal headers, badge names, toast messages &mdash; must use **Title Case**:
- ✅ `Confirm Your Email Address`
- ❌ `Confirm your email address`

### 2. Mobile-First Optimization
Target **360px** viewport width first:
- Use GPU-accelerated CSS properties (`transform`, `opacity`).
- Avoid full-viewport `background-position` animations.
- Cap device pixel ratio (DPR) to maintain 60 FPS on mobile.

### 3. Never Hand-Edit `dist/`
The `dist/` directory is generated by `build.js`. Manual changes will be wiped on the next build. Always modify source files and run `npm run build`.

### 4. Preserve Mumbai Traffic Context
The Traffic Simulator is modeled on Mumbai traffic environments. When building features or levels, preserve authentic road dynamics, local signage, and practical educational value.

### 5. Generate Published Numbers, Never Hand-Write Them
Counts published on the site (career pathways, countries, levels, applications)
come from the data. Change the data, then run the fact scripts and update the
copy:

```bash
node scripts/fact-check.js
node scripts/fact-terra3d.js
node scripts/fact-codepaths.js
```

### 6. Keep Internal References Alive
After adding, moving, or deleting a page or asset, run:

```bash
node scripts/audit-pages.js
```

It resolves every internal `src`/`href` against the built tree. The production
checker only warns about missing references, so a page can pass CI and still
404 in production.

## Pre-Commit Verification Checklist

Before pushing any changes:

- [ ] `npm run build` completes with exit code 0.
- [ ] Postbuild production check passes.
- [ ] Postbuild SEO check passes.
- [ ] Postbuild security regression check passes.
- [ ] `node scripts/audit-pages.js` reports no missing references.
- [ ] `npm run lint` and `npm run typecheck` pass.
- [ ] `npm test` passes.
- [ ] Tested on both desktop and 360px mobile viewport.
